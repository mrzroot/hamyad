Three islands, zero bridges

Decide something in a claude.ai chat and Claude Code never hears about it. Let Claude Code learn something in a session and the chat never sees it.

Claude Code

CLAUDE.md you write by hand, plus auto memory in ~/.claude/projects/…/memory: on this machine only.

Claude.ai Projects

Project knowledge, custom instructions and a per-project memory, all inside claude.ai. The GitHub integration is read-only and syncs only when you press Sync now.

Claude Desktop

Its own chats and its own local MCP servers. Nothing it learns about your repo goes back into the repo.

Sources and the full survey of existing tools: RESEARCH.md

    How it works
    
  
      
    
    1. 
      1
      
      Any Claude writes
      
      
      The same seven MCP tools everywhere: brain_remember, brain_search, brain_update, brain_context… Claude.ai reaches them through a remote connector, Claude Code and Desktop through stdio.
      
    
      2. 
    
    2. 
      2
      
      Git stores
      
      
      One Markdown file per entry under .brain/. From chat, each write is a commit made through the GitHub API by a tiny Cloudflare Worker. Unique file names mean two writers never conflict.
      
    
      3. 
    
    3. 
      3
      
      Claude Code pulls
      
      
      A SessionStart hook fast-forwards the repo, refreshes a generated block in CLAUDE.md and tells Claude exactly what changed in chat since its last session.
      
    
      4. 
    
    4. 
      4
      
      Sessions hand off
      
      
      A SessionEnd hook turns the transcript into a short summary (prompts, files, commits, outcome) without any LLM call, commits it and pushes it, so the chat side picks up where the CLI stopped.
      
    
      5. 
  
    

  

    



    
  
    Set it up in ten minutes
    
  
    
    
    
    
  
    
  
    
    
    Inside your repo. init creates .brain/, registers the MCP server in .mcp.json, merges two hooks into .claude/settings.json and adds a generated block to CLAUDE.md, without touching anything that is already there.
    

    npm i -g https://github.com/mrzroot/hamyad/releases/download/v0.1.0/hamyad-0.1.0.tgz
cd my-project
hamyad init
git add .brain .mcp.json .claude/settings.json CLAUDE.md
git commit -m "Add hamyad brain" && git push
hamyad absorb    # optional: copy Claude Code's local auto memory into the shared brain
    
  
    
  
    
    
    claude.ai calls connectors from Anthropic's cloud, so the server must be public. The free Workers plan is enough, and because Anthropic makes the call, a local block on workers.dev does not matter.
    

    git clone https://github.com/mrzroot/hamyad && cd hamyad && npm ci && npm run build
cd worker                       # set GITHUB_REPO in wrangler.toml
npx wrangler deploy
npx wrangler secret put GITHUB_TOKEN   # fine-grained, one repo, Contents: read/write
npx wrangler secret put HAMYAD_TOKEN   # long random string

# claude.ai → Customize → Connectors → Add custom connector
#   https://hamyad.<you>.workers.dev/mcp/<HAMYAD_TOKEN>   (No sign in)
# then paste the output of `hamyad connect` into the Project's custom instructions

    {
  "mcpServers": {
    "hamyad": {
      "command": "hamyad",
      "args": ["mcp", "--dir", "/path/to/my-project", "--source", "claude-desktop"]
    }
  }
}
    
  
    

    



    
  
    Things hamyad will never do
    
  
      
    
    • Rewrite your history. Pulls are fast-forward only.
      • 
    
    • Push your work in progress. It pushes only when every unpushed commit is a brain: commit.
      • 
    
    • Commit your own edits to CLAUDE.md. Only its generated block is ever committed.
      • 
    
    • Run a public server without a token. Workers and hamyad serve refuse to.
      • 
    
    • Lock you in. It is a folder of Markdown. Delete hamyad and the notes stay.

    Questions
    
  
    Does it need an Anthropic or OpenAI API key?
    No. Claude does the thinking in whichever app you use; hamyad only stores and serves. Session summaries are built from the transcript without any model call.
    
  
    I am in Iran. Will the connector work?
    Yes. claude.ai connects to your Worker from Anthropic's servers, not from your device, so domestic filtering of workers.dev does not affect it. You may need open internet once to deploy.
    
  
    What about teams?
    Everyone with repo access shares the brain through git. For the chat connector, v0.1 uses one shared token per deployment; OAuth per person is on the roadmap.
    
  
    Can I edit entries by hand?
    Yes, in your editor or on github.com. A file without frontmatter works too: its first heading becomes the title.
